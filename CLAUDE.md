# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Sense Calibrator: a browser tool that diagnoses and hardware-recalibrates drifting PS5 DualSense analog sticks over WebHID. Pure static site — vanilla ES modules, no build step, no runtime dependencies, no linter. `package.json` exists only to run the tests (`npm test` = `node --test`); dev-only tooling lives under `ops/` and `test/` and is never loaded by the page.

## Running

WebHID requires a secure context (`file://` does not work) and only works in Chrome/Edge. Serve the folder over HTTP:

```sh
python3 -m http.server 8000
```

A preview server is configured in `.claude/launch.json` (name `sense-calibrator`, port 8741). Note: actual controller interaction cannot be tested headlessly — it needs a physical DualSense connected over **USB** (Bluetooth is detected and rejected for calibration).

## Architecture

ES modules under `js/`, loaded from `index.html`:

- **`js/ds5.js`** — DualSense HID protocol layer, no DOM. The `DS5` class wraps a WebHID device: calibration commands (feature reports `0x82` send / `0x83` response, checked against expected status words), NVS lock/unlock/status (`0x80`/`0x81`), device info, battery parsing. Protocol sequences derive from the dualshock-tools project. Key invariant: feature report buffers must be padded to the size declared by the HID descriptor (`allocReq`) or the firmware silently discards the command. Every request/response pair runs under a per-device mutex with a 1,000 ms timeout (`HID_REPLY_TIMEOUT_MS`, timers injectable for the simulator). A timeout **poisons** the instance: every later command throws before sending anything, until a reconnect builds a new `DS5`, so a late reply can never be read as the answer to another command. A timeout (or any failure after the send went out) on a commit command — `calibEnd`, `rangeEnd`, `nvsUnlock`, `nvsLock` — sets `error.committed`, and the page raises `unsaved`. `flash()` checks the `0x81` report id, never retries the unlock, retries only the lock once if it fails after a successful unlock, and reports a timeout as "memory state unknown" (`nvUnknown`). `rangeEnd` returns `{ alreadyClosed }` for code 3 (nothing committed). Connecting only reads (`queryNvStatus`, serial, report `0x20`); there is deliberately no auto-lock until hardware check H3. The firmware build date is parsed locally (`parseBuildDate`) and never sent.
- **`js/calib/`** — the calibration algorithm, with no DOM and no direct timers or HID access. The page and the simulator run the same code.
  - `measure.js`: pure measurement — `parseSticks` (report `0x01` bytes → sticks), `median`, `extractStableSamples`, `analyzeDrift`, `summarizeResult`, `verdictFor`, and the `DRIFT_*` thresholds.
  - `sampling.js`: `waitForStable` and `measureOffset`, driven by a stick `source = { subscribe(fn) → unsubscribe, sticks, now() }` and a `clock = { sleep, setTimeout, clearTimeout }`. In the page the source is fed by HID input reports; in the simulator by a virtual DualSense.
  - `quick.js`: `runQuick({ controller, source, clock, isCurrent, isCancelled, force, onProgress, log, params, meta }) → { session, outcome, committed, needsPowerCycle?, … }`. Never throws: an HID error becomes `outcome: 'error'` with `committed` (true once any `calibEnd` succeeded, a `calibBegin` repair committed — the `{ committed }` that `DS5.calibBegin()` returns is read, not only the thrown flag —) and `needsPowerCycle` when it exited between a successful `calibBegin` and its `calibEnd` (error, refused sample, failed `calibEnd`, disconnect): the page then marks the power-cycle lock exactly as for a stall (also on the `disconnected` outcome), because the next `calibBegin` would be refused and its repair `calibEnd` would commit the partial session. `repairStaleSession: false` makes a refused `calibBegin` an `error` with `needsPowerCycle` instead of a repair. A `stalled` result carries `pass` and `committedBefore`, so the copy says "nothing was committed" only for a first pass with no repair commit. A session that was only opened is not a commit, so it does not raise `unsaved`. Every commit also emits `onProgress({ phase: 'committed' })`, and the page raises `unsaved` (and the tab flag) right then, not when the run returns: an unplug in pass 2 must still find it set. Other outcomes besides `classifyOutcome`'s: `preflight`, `already-centered` (no command; `force` bypasses), `moved` (hold failed before a later pass), `stalled` (pass abandoned without `calibEnd`, `needsPowerCycle`), `disconnected`, `catastrophic` (verified residual ≥15%). `QUICK_DEFAULTS` holds the constants; a variant is a `params` override. The opt-in recovery pass after `catastrophic` is `runQuick({ …, force: true, params: { maxPasses: 1 } })`.
  - `quick-policy.js`: pure rules — `decideAfterPass` (stop rule) and `classifyOutcome` (which result the user is told). The caller carries the returned state (`prevWorst`, `bestWorst`, `bestPass`, `extraUsed`) into the next pass. Outcome precedence: catastrophic > worse-than-start > lost-ground > worn > residual-deterministic > within-1-step > centered. Plateau continuation (`plateauExtraPasses`) ships at 0 and is enabled only as a separate rollout step. Neither recovery nor plateau continuation adds a pass within one lattice step of the ceiling (`QUICK_CEILING_MARGIN` = 1 LSB·√2, reason `near-ceiling`): from a 14.52 plateau one more pass can land at 15.3.
  - `lattice.js`: the 8-bit lattice (1 LSB = 0.784%, floor 0.555%, one step 1.240%) and **`GRID_TABLE`, the single source of truth** for offset tiers, labels, outcome classes, the precision-test Center score and recommendation keys, plus the Pinned/Moving overrides. `formatOffset` is the only offset formatter (`0.6% · at floor`, `1.2% · 1 step`); `decodeOff` splits an offset into per-axis steps. It imports nothing: `measure.js` takes `DRIFT_OK_MAX`/`DRIFT_MILD_MAX` from it and `verdictFor` goes through the table. `ops/calib-telemetry/quality-report.mjs` loads it too. `DRIFT_OK_MAX` (<1.2, the v1 KPI and stop target) is not raised; "within 1 step" (≤1.25) is a label and a second metric only.
  - `wizard-gate.js` (WS7): the guided wizard's sample gate. Each `calibSample` needs (1) both sticks to have reached the corner since the previous sample (projection toward it ≥0.6, tracked from HID reports), and (2) a stable window (300 ms, 5 s timeout, `QUICK_STABLE_SPREAD`) whose mean is within max(4 LSB, 3·start noise), capped at `maxTol` = `DRIFT_MOVE_SPREAD` (8% ≈ 10.2 LSB per axis, so √2·8% ≈ 11.3% on a diagonal, always inside the escape radius), of the **in-session** rest reference, the first stable window after `calibBegin` (within 50%). Same frame as the samples, as in Quick: `wizard.before` is taken before `calibBegin` and is used only for the before/after comparison (`wizardComparison`, both in the calibrated frame) and for the noise. Never a sample on a timeout, no automatic relaxation; after 2 timeouts the page offers a confirmed, locally logged escape for a creeping stick. The escape never drops the position check: it widens it to a fixed radius of `escapeLsb` (24 LSB ≈ 18.8%, per stick, Euclidean, via `waitForStable`'s `nearRadius`) around the same in-session reference, and widens the spread gate to `DRIFT_MOVE_SPREAD` (never beyond). A thumb held still at a corner or on the rim is never sampled, escape or not; with no reference there is no sample at all (an escape taken before the reference still captures one, with the wider spread gate). Start waits for still sticks before sending anything, and rejects a disturbed start measurement before `calibBegin` (`checkBefore`: p95 noise above `DRIFT_MOVE_SPREAD`/2 = 4% on either stick, or a stable fraction below `DRIFT_MIN_STABLE`): a touch in that second used to push the tolerance to ~81 LSB and sample a thumb held ~57% from the reference. The cap is enforced again in `restTolerance` and `sampleGateOptions`, so no caller can widen the normal check past it.
  - `range-coverage.js` (WS7): range tracking fed from HID reports (rAF only draws). Per stick: 36 sectors with chord-conservative fill between samples ≤30° apart, coverage threshold on `min(1, globalMax)`, per-direction extents, turns counted with 30° hysteresis. **Done** needs ≥90% sector coverage, every direction ≥0.9·maxAbs, ≥2 turns and a change of direction (≥0.5 turn the other way) on both sticks. The page opens Range on an intro step that sends nothing (Cancel and Esc close it) and says, before `rangeBegin`, that once started the only way out without finishing is turning the controller off; with a known pinned axis the intro also warns that the range may never complete (H12). After 15 s an incomplete range can close only through a confirmed **Finish anyway** that names what is missing, and never with a direction under 0.5 (no way to close a zero-motion session; the only exit is turning the controller off). `circularityRms` drives the post-range check ("about 7–10% is normal").
  - `rest-noise.js`: `createRestNoiseCollector()` — summarises 30 s windows of resting stick readings (median, p50/p95/max distance in LSB, per-axis spread, excursions ≥1/2/4 LSB, report intervals) for the v2 `rest` event; drops a window where a stick moves past `DRIFT_MOVE_SPREAD`, restarts on a report gap over 1 s, at most 8 per page load. Pure: the page decides when collection is allowed.
  - `ops.js`: `createOpGate()` — the single-operation `busy` flag with an epoch token (`beginOp`/`endOp`/`reset`). Only the token that currently owns the flag can clear it: an orphan loop that exits after `teardown` (`reset()`) cannot release the `busy` of a newer operation.
- **`js/ui/`** — pure UI logic, no DOM access except the tiny renderers, no HID, no timers:
  - `outcome.js`: the persistent `#calib-outcome` panel (views for Quick, Guided and Range results, per-stick before → after through `formatOffset`), the **Write lock** (`writeLockFor`: `disabled` for catastrophic ≥15%, pinned, stalled/needs power cycle, poisoned, incomplete or `alreadyClosed` range; `guarded` — warning, Cancel focused, second confirmation — for worse-than-start, lost-ground and unverified results; it also checks the numbers, not only the outcome label; an `already-centered` Quick replaces the center state with what it just measured, `committed: false`, so an older catastrophic or worse-than-start verdict never keeps Write off on sticks measured centered), the drift-test message and routing (≥15% → Guided, Pinned → Range then Guided, tentative until H12), and `render` for `ops/sim/replay-telemetry.mjs --renderer`. Invariants: at 15% or more nothing reads as success and Write is disabled; power-off advice only with NVS `locked` (C0-11) — the power cycle needed to clear an open session or a poisoned controller is a different instruction and is always given; a timeout (`error.timeout`/`poisoned`) gets its own view (`POISONED_OUTCOME`: "may or may not have been applied", no earlier pass, no save, no Restart, the raw HID text only in the log); "unplug" only in the sentence saying it is unverified (H11). `FIX_RATE` is the WS3 report figure (PG) and must be refreshed at release. `test/outcome.test.js` covers one case per `GRID_TABLE` row.
  - `hands-off.js`: the green/amber/red movement meter (spread over the last 250 ms, thresholds `QUICK_STABLE_SPREAD` and `DRIFT_MOVE_SPREAD`), fed by HID input reports in the Quick and Guided modals; reusable by the precision test. It sees movement only — a thumb holding a stick still is "Not moving" — so its labels never say "hands off" or "at rest". The page forces the `held` level ("Stick held: let go") whenever it already knows about a hold: Quick phases `held`/`stalled`/`unstable` until the next sample or pass, a failed Quick preflight (except when the last drift test put a stick at Guided-only or Pinned: nobody is touching it, so `quickPreflightRoute` in `outcome.js` says so first and the main button opens Guided, or Range for Pinned), a Guided stick still at the corner (`cornerDot`), and after a Guided gate timeout while a stick is outside the in-session reference tolerance. No new thresholds.
  - `connect-help.js`: the empty-chooser checklist and plain-language WebHID errors.
- **`js/app.js`** — UI wiring only for calibration: connection/reconnect, input report routing (`stickSource`, `pageClock`), drift test, the Quick modal around `runQuick` (busy, messages, outcome panel, telemetry, unsaved), 4-corner guided wizard, range calibration with coverage bins, NVS write flow, telemetry. The Quick loop gets the `ds5` captured at click time and `isCurrent: () => ds5 === controller`; after a replug the orphan loop sends nothing more and touches neither the new operation's `busy` flag nor its modal. A stalled pass, or any error or disconnect that leaves a center session open (Quick or wizard, tracked by `sessionOpen`), marks that controller (`markPowerCycle` → `powerCycleLocks`): Quick, wizard, range and Write are refused. The lock follows the controller, not the `DS5` object — Disconnect + Connect, a replug or a reload is not a power-off and the session is still open in the firmware — through a map keyed like `rangeWriteLocks` (salted controller key → `{ controller, reload, exempt }`, read through `powerCycleLockFor(controller, key)`; `powerCycleApplies()` for the connected one). Same rules as the range lock: a lock on B never replaces A's, a different readable serial suspends a lock instead of clearing it (A → B → A, both with a session open, finds A blocked again), a keyless lock (unreadable serial) applies to every controller except those that later showed their own restart (`exempt`), and a restart or confirmed power-off clears only the lock of that controller (`clearPowerCycle(reason, controller, key)`: its keyed lock, plus an exemption from the keyless one; a controller with no readable serial clears only the keyless lock, never a keyed one, and the reminder stays up). Persistence: a `sessionStorage` flag (`sense-power-cycle-in-tab`, value `'1'`, no device identifier — keys are salted per page and never stored), kept while any lock is in the map. A fresh page turns it into one keyless `reload` lock: every controller is blocked until it shows its own restart, and a single restart does not remove the flag (the page can't know how many controllers had a session open). The format is unchanged, so a value from an earlier page load or version is honoured the same way, and any non-empty unknown value blocks too. The flag is also written synchronously **before** every `calibBegin` (Quick through `runQuick`'s `onSession('opening')`, Guided directly; `openSessionGuard` also sets `repairAllowed = false`) and released only after that session's `calibEnd` succeeds or the run ends with no session open: a reload or a closed tab while a session is open (between Guided corners, mid-Quick sampling) never passes through `fail()`/`catch`, and the fresh page must come back blocked and never repair. A `calibBegin` that went out but got no answer (reply timeout, receive error after the send) throws with `openSession: true` (`DS5.calibBegin`), so it is locked like a refused begin. On reconnect the outcome panel shows `powerCycleReminderView`; the lock clears only on evidence of a restart — the HID `disconnect` of that controller within 5 s of a Restart whose send resolved or failed with the device closed (`DS5.reboot()` returns `{ sent }`; a send refused with the device still open keeps the lock and says the restart didn't reach it) — or when the user explicitly confirms a power-off ("I already turned it off"). Second line of defence: once the tab has left a session open, `calibBegin({ repair: false })` is used, so a refused begin fails with `openSession` (and re-marks the lock) instead of committing the partial with a repair `calibEnd`. The Disconnect confirmation says disconnecting is not the power-off it needs. The wizard and range flows are bound to the controller captured at their start too. A range left open, interrupted, finished incomplete ("Finish anyway"), reported already closed (code 3) or failed after a possible commit sets a range write lock for that controller: Write is disabled until a complete range replaces it. `finishRange` captures the controller key before `rangeEnd` and sets the lock even when the controller was unplugged while `rangeEnd` was in flight (resolved late, timed out, or failed after teardown: an unknown outcome locks as `error`); only the UI side is skipped then. The lock does not clear on disconnect: whether the range in RAM survives a USB unplug without a power-off is H11 (unverified), so a replug of the same controller keeps it and warns that the incomplete range may still be active, and no copy ever presents a reconnect (or a power-off, H10) as a way to re-enable Write. The lock follows the controller through `rangeWriteLocks` (controller key → reason), keyed by a per-page salted SHA-256 of the serial (never the raw serial, never sent anywhere); `rangeLockFor(deviceKey)` says which lock applies. A controller with a different readable serial does not inherit it, but the lock is **suspended, not cleared** (as the power-cycle locks): A → B → A finds Write disabled again on A, and a lock set on B never replaces A's. An unreadable serial counts as the same controller: a lock with no key applies to every controller until that controller completes a range, and a controller with no readable serial never clears a keyed lock. A complete range clears only the lock of the controller it ran on. It is folded into WS5's general Write lock: `currentWriteLock` passes it to `writeLockFor` as a range `incomplete`/`alreadyClosed` state alongside the displayed `rangeState`, and `setRangeWriteLock` only records it and calls `updateWriteLock` (clearing it never re-enables Write while another reason holds). Range results go to the persistent `#calib-outcome` panel, not toasts. A keyless `sessionStorage` flag preserves the lock conservatively across reloads; no serial or salted per-load key is stored. A complete range goes to a check step (one more turn, circularity, no HID command), then the drift test. The local range and wizard events stay local; telemetry v2 sends its own reduced `guided` and `range` events (see Telemetry).
- **`js/quick-center-guard.js`** — the conservative Quick startup radius/hold policy (see below).
- **`js/game.js`** — precision test v4 (WS8), three checks that measure the controller, not the user: **Center** (hands off: offset and noise), **Return** (4 prescribed flicks, 1 round) and **Range** (36 bins from `range-coverage.js`, 25 s cap). `createPrecisionTest()` is a pure state machine (no DOM, no timers; time comes from the caller) and `initGame()` is the DOM shell. Sampling is per HID report through `deps.subscribe` (app.js wires it to `stickSource`); rAF only draws and notices a report gap. Rules: a gap over 100 ms or a hidden tab shows "Interrupted" with Retry; the start is "ready once released" (the WS5 hands-off meter green for 400 ms, or still for 1.5 s on a noisy stick, 12 s cap with an explanation); Center uses 30-report windows, drops those with spread above `DRIFT_MOVE_SPREAD`, treats a rest point that creeps more than 4 LSB between windows as a touch, needs 60% surviving windows, retries automatically at most twice and never scores a touched run; its score is `centerScoreFor` from `GRID_TABLE` (0.555→100, 1.24→90, 3.5→60, 8→0). Return rejects a release slower than 80 ms from r≥0.75 to r≤0.25 ("That looked guided"); a skipped or timed-out Return reads "Not measured", never 0. **Headline**: Calibration = the weaker stick's Center score, Hardware = its Stability (noise; 1 LSB→95, `QUICK_NOISE_WORN`→75, 4%→0), with Return and Range as information-only sub-lines, and one plain sentence. "Previous" is stored under `senseGameLastScore.v4`, keyed by `SHA-256(salt‖serial)` with a random salt kept in `localStorage` (`senseGameSalt.v1`); neither the serial nor the key is stored in the value or sent anywhere. Before/after uses a 1-LSB rule on the per-axis medians (not on the radius). Every wait carries a `why` in `#game-why`; `#game-instr` and `#game-why` are written only on change. The copy's duration ("about 15 seconds") is the rounded median of the model run in `test/game-scoring.test.js`, which fails if the two drift apart. The local `game` event carries raw metrics for re-tuning the Return/Range anchors, never the serial or key. Talks to app.js only through injected deps (`getSticks`, `subscribe`, `getSerial`, `isAvailable`, optional `onReport`); never touches HID.
- **`js/sensitivity.js`** — experimental local sensitivity finder. Compares right-stick tracking across three virtual control speeds, creates a universal FPS aim profile, then optionally maps it to game-specific starting settings. It receives stick state through injected deps, never touches HID, and keeps results in localStorage.
- **`js/playtest.js`** — experimental fixed-timestep FPS-style controller lab. Separates browser frame pacing from raw HID report timing and scores tracking, movement coverage and simultaneous two-stick use. It receives live stick state and HID sample notifications through injected deps.

Sensitivity Finder and Gameplay Lab are excluded from the public product and search metadata. They are available only on localhost with `?preview=1` while they are developed and tested. Do not promote or expose them in the hosted page without an explicit release decision.

## Domain constraints worth knowing

- Applied calibration lives in controller RAM until explicitly written to NVS (unlock → lock cycle via `flash()`); power-off is expected to revert it to the last saved calibration (hardware check H10, not run yet: the copy says "should"). The UI tracks this as the `unsaved` state — don't break that safety net. The save step (`#banner-unsaved`, with `#btn-flash`) sits right under `#calib-outcome`; when `unsaved` is raised it is revealed on the next frame, or when the open modal closes (`revealSaveStep`): scroll into view, one `saveCue` pulse (none under reduced motion), one announcement. With Write `disabled` it takes `data-lock="disabled"` (muted, outlined button, reason in `#banner-lock`) and neither scrolls nor pulses. `#save-reminder` is a fixed bar shown while `unsaved`, no modal is open and the block is out of view (IntersectionObserver); its button opens the same guarded Write modal, or scrolls to the reason when Write is disabled. Nothing opens the Write modal automatically. A `sessionStorage` flag (`sense-unsaved-in-tab`) survives a reload and shows a "may still be active" banner; it deliberately stores no device identifier, and only a successful flash or Dismiss clears it. Disconnect asks for confirmation while `unsaved` or `busy`. The serial is masked by default.
- Only the standard DualSense (`054C:0CE6`) is supported; DualSense Edge and DualShock 4 are not.
- Drift measurement classifies stability by signal *spread* within a short window, not absolute stick value. Stability alone cannot prove that the user released the stick. Quick calibration has a separate conservative startup policy in `js/quick-center-guard.js`: both sticks must stay within 15% radial offset for 300 ms, with at least 10 fresh HID reports and no gap over 100 ms. The baseline must also stay within this radius, and a second centered stability hold is required before any calibration command. This is an initial safety policy, not a hardware diagnosis or a threshold validated from production data; a genuine resting offset outside it requires guided calibration. Failed preflight leaves controller RAM/NVS untouched and restores retry/cancel. Cancelling a blocked attempt resumes the drift test.
- The NVS-specific calibration block requires a **confirmed** state: NVS `unlocked` (a "temporary" calibration could land straight in memory) or a poisoned controller. `unknown`/`error` show a warning chip and still allow it; firmware built in 2020–2021 asks for confirmation once per connection. A flash counts as saved only with no exception and a final NVS status in `{locked, pending_reboot}`. A real DualSense returned `locked` as raw `0x03030201` (`81 03 03 02 01`) after a successful flash; `error`, `unknown`, timeout and `unlocked` keep `unsaved` true and report “Save not confirmed.”
- Quick safety invariants (`js/calib/quick.js`, WS1). **One frame per check**: the centered hold (15% radius, calibrated frame) runs before *every* `calibBegin`; inside a session each sample needs a stable window whose mean is within 4 LSB of the in-session reference (the first stable window after `calibBegin`, itself within a 50% plausibility radius); the verify after `calibEnd` is again in the calibrated frame. Never compare a reading taken before `calibBegin` with one taken during the session, or a session reading with one after `calibEnd`. **12 samples per commit**: a pass that cannot collect them (15 s, prompt, then 30 s more or Cancel) is abandoned without `calibEnd` and the controller needs a power cycle. **Never `calibSample` after a timeout**: a timed-out wait widens the gate (still ≤ `DRIFT_MOVE_SPREAD`; sticky `gateOff` now only pins it at the maximum) but never samples blindly. Starts below `DRIFT_OK_MAX` (both sticks at the floor) send no command; 1.24 starts calibrate. A verified residual ≥15% ends the loop as `catastrophic`, with no automatic recovery pass.
- One calibration at a time: app.js guards with the op gate (`ops.busy`, `js/calib/ops.js`), the former `busy` flag. Alzalo *prima* di qualunque `await` lungo (es. la misura iniziale del wizard), non dopo: la finestra tra il click e l'alzata è sufficiente ad avviare una seconda calibrazione.
- Ogni `calibEnd()` è applicato subito dal firmware e sovrascrive il precedente; il codice non rilegge mai la calibrazione dal controller, quindi **una passata peggiorativa è irreversibile**. Per questo `quickCalibrate` non si ferma su una regressione (userebbe il budget residuo per recuperare), tiene `bestWorst`, e avvisa se il risultato finale è peggiore della migliore passata o del punto di partenza. Non reintrodurre un `break` sul semplice "non è migliorato". `bestWorst` parte dal punto di partenza: un plateau peggiore dell'inizio non è mai "convergenza" (con l'altro stick già a 0.555 si concede al massimo una passata in più, perché ogni passata ricalibra entrambi gli stick). L'unico arresto anticipato è il tetto fisico: una passata verificata ≥15% (il raggio del guard) chiude il ciclo con esito `catastrophic`.
- Il gate di stabilità non deve mai superare `DRIFT_MOVE_SPREAD`: sarebbe più permissivo della soglia con cui l'app stessa dichiara "questa è una mano sullo stick". Decade verso `baseGate` a ogni passata; `gateOff` invece resta sticky, perché riaprirlo costa 5 s di timeout per campione. `Escape` dismisses only the modals in `ESC_DISMISS` and never while `busy` — the range modal only on its intro step (before `rangeBegin`): an open range session must be closed with `rangeEnd()` rather than abandoned, and its Cancel is hidden.
- Stick sampling is always driven by HID input reports (`stickListeners`), never by `setInterval`/`setTimeout`. The drift test too: it completes only on fresh, continuous reports spanning its full deadline (samples capped at 3× the expected count), and rAF only draws the progress bar and catches the "no data" case: page timers are throttled in background tabs, and a fixed interval both under-samples the ~250 Hz report rate and duplicates identical samples, which corrupts the stability fraction and the effective duration of `DRIFT_WINDOW`.

### Audit safety invariants (2026-09-28)

- A center result that is catastrophic, pinned, regressed or unverified, and an incomplete or uncertain Range, keep their Write lock for the same controller after USB reconnect. Each lock has a keyless `sessionStorage` flag for reload: the salted per-page controller key cannot be reconstructed, so the next page blocks conservatively until a new complete result replaces the risk. No device identifier is persisted or sent.
- A Guided `calibBegin` that might have reached firmware is finalized on disconnect or `pagehide`, including between corner clicks; an applied `calibEnd` with no final verification remains guarded. Range is provisionally locked before `rangeBegin` and remains locked on uncertain begin, interrupted rotation or failed/uncertain `rangeEnd`. Every interrupted flow emits one v2 event. A late ACK may refine a Range lock but never clears an interrupted result or emits twice.
- HID decoding stays inside the mutex/timeout transaction: malformed or mismatched calibration replies preserve `openSession`/`committed` when a command might have reached firmware. Restart timeouts poison the connection. No new HID command or write path is introduced.
- Stability requires fresh HID reports, with gaps over 100 ms resetting a hold or measurement; a full stated duration must be observed. Guided rejects a moving final measurement, Quick's noisy verification considers all reports, and both compare worsening per stick. The 12 samples per Quick commit, no `calibSample` after timeout, one frame per check, `bestWorst`, gate ≤ `DRIFT_MOVE_SPREAD` and the 15% ceiling still hold.
- Flash status is verified on the controller that began the operation, and late calibration events can only claim that controller's save period and operation epoch. Revoked consent is checked immediately before every v1 or v2 upload. The v1 payload and `ops/calib-telemetry/contract/*` remain unchanged.

## Accessibility (WCAG AA)

- **Focus is owned by the modal block in `js/app.js`** (`openModal`, `closeModal`, the Tab trap, `updateBackgroundInert`). Focusable means visible: `visibleFocusables` filters with `checkVisibility()` (ancestor-walk fallback where it is missing), so buttons inside a hidden container never become the trap's first or last element. Every `.modal-panel` has `tabindex="-1"` and takes the focus when the modal has nothing active (range at open) or when the focused control is disabled or hidden mid-run (Quick and Guided running, game Start, Skip and Retry); a `MutationObserver` on the open modal does this, because disabling a focused button fires no reliable focus event. Initial focus prefers the first visible `[data-autofocus]` in DOM order, else the first focusable, else the panel. Other code only sets or clears `data-autofocus` (WS5 on Cancel/Close; static on Calibrate now, wizard Start and game Start) — never calls `focus()` on modal content itself, except `game.js` moving the focus to the score when the report replaces the hidden Start. The Quick modal must never open on the telemetry checkbox.
- The **`[hidden]` rule** (`display: none !important`) must stay: `hidden` alone loses to class `display` rules such as `.action { display: flex }`.
- **Announcements:** `#quick-msg`, `#wizard-msg`, `#game-instr`, `#game-why` and `#range-hint` are `role="status"`; `#drift-status` and `#calib-outcome` are polite live regions. `#save-step-live` (`role="status"`, visually hidden) announces the save step once per unsaved calibration. Errors use `toast(msg, ms, { alert: true })`, which also writes the text into the separate `#alerts` (`role="alert"`) and marks the visible toast `aria-hidden`. Write status text only when it changes (`setLive(el, value, { html })` in app.js compares against the DOM; game.js writes `#game-instr` and `#game-why` through its own compare-first `setText`): rewriting a live region with the same text can be announced again, and the range tick (every 120 ms, on both the range session and its check step), the quick progress events and the game's per-frame view would otherwise do so continuously. Changing text must not chatter either: `#range-hint` carries milestones only (`rangeStatus` counts whole turns, the check step whole percent) and changes at most once per second (`RANGE_HINT_MIN_MS`), except on completion; a counter that moves with the stick never goes into a live region. Progress bars are `role="progressbar"`; `aria-valuenow` and the wizard's "Step n of 5" (`#wizard-step`, the dots are `aria-hidden`) are derived from `style.width` and the dot classes by observers in the accessibility block, so the code that drives them sets only the visual state. Dial canvases are `role="img"` with a label; the drift verdict detail is visible text (`#verdict-*-detail`), never a `title`.
- **Motion:** durations and curves are tokens on `:root` in `css/style.css` (`--motion-fast` 160 ms exits, `--motion-base` 240 ms entrances, `--motion-layout` 280 ms for space opening with `--ease-layout`, `--motion-cue`, `--motion-shift`); `app.js` reads them through `motionToken`/`motionMs` (`MODAL_CLOSE_MS` must equal `--motion-fast`). In-flow blocks (`.callout`, `.save-step`, `.outcome-card`, `.banner-lock`) keep `hidden` synchronous: the exit is a CSS transition with `transition-behavior: allow-discrete` on `display` that closes their space; entrances use `@starting-style`, except the outcome panel, whose growth runs in `growBlock` (WAAPI) *after* `showOutcome` has chosen its scroll on the final geometry, and never while a modal is open or closing (`pageCovered`). The save step enters by opacity only because `revealSaveStep` measures it. `#save-reminder` is hidden by `visibility`, not `display`, with an entry delay so it doesn't flash during that scroll. Dials, meters, progress bars, live readouts and modal-internal instructions never animate. Reduced motion: no transform, no height change; entrances fade.
- **Contrast:** text tokens ≥4.5:1 on white and `--bg`; component edges, state dots and dial guides use `--edge` (`#8f8f8a`, 3.25:1 on white) — the canvas `MID` constant in `app.js` is the same value. Focus rings turn white on dark surfaces. `color-scheme: light` only; a dark theme is out of scope (see the plan's "not now").
- The dials' **×10 zoom** is drawing only: the edge is 10%, the dashed ring is `CENTERED_MAX` and the dots are the byte lattice near the center, so the 0.555% floor and the 1.240% step are visible. It never touches measurements or verdicts.

## Telemetry

Every significant action emits a typed local event via `recordEvent(kind, data)` in app.js. Ogni evento porta `sid`, un valore casuale per caricamento di pagina mai persistito: collega gli eventi di una singola visita, non due visite tra loro. `summarizeResult` include `xy` (componenti per asse): `off` è la loro ipotenusa, quindi senza `xy` la direzione del drift è perduta. Events always go to `localStorage` (`sense-calib-sessions`, capped at 200; on a quota error the history is trimmed to 50 and the write retried, and only a `SecurityError` disables storage for the page).

The network contract is deliberately narrower. `js/telemetry.js` maps only complete `quick` sessions (no `aborted` marker, e.g. `'moved'`, and no local-only `truncated: 'time-limit'`) to the strict nine-field v1 API schema and strips `kind`, `sid`, `xy` and every unsupported field. Do not widen the v1 payload or allow unknown properties: v1 stays as it is for old cached pages and for the KPI baseline, and complete Quick sessions keep going to it.

**Telemetry v2** (`js/telemetry-v2.js`, `POST /api/calib/v2/events`) sends typed events, one per request: `quick`, `guided`, `range` (one per calibration that sent a command), `flash` (each Write attempt), `save` (how an unsaved period ended) and `rest` (resting-noise summaries from `js/calib/rest-noise.js`). The contract is **one file**, `ops/calib-telemetry/contract/events-v2.schema.json`, with `events-v2.fixtures.json`; the service keeps byte-identical copies (`subralabs-v2/code/calib-telemetry/contract/`) and both test suites pin the same SHA-256, so changing it means copying both files to the service, updating both pins and regenerating `js/telemetry-v2-schema.js` (`node ops/calib-telemetry/contract/sync-schema.mjs`) and the OpenAPI components (the service's `contract/openapi-components.js`). Every event is validated in the page with the same JSON Schema subset the server uses before it leaves the browser; an unsupported schema keyword throws. Rules: no serial, device key, error text, free text or client timestamp in any field (builders map to enums and round numbers; `flashResultFor` classifies from `error.flashStage`/`nvUnknown`, never the message); `sid` (`V2_SID`) is its own random value, never `SESSION_ID`, which the local history writes to disk; `seq` orders the visit; `app` (`TELEMETRY_APP_BUILD`, YYYYMMDD) is bumped when what is measured changes (20260928 for this sampling audit). The save period opens in `setUnsaved(true)` and closes in `doFlash` (`saved`), `teardown` (`disconnected`) or `pagehide` (`left`, keepalive, best effort: the report counts a missing save as unknown); its `ref` is the `seq` of the last calibration event from the same internal controller and operation epoch (`emitCalibV2` may seed a period that opens within 5 s, but an orphan event cannot claim the next controller’s period). Rest noise is collected only with a controller, a visible page, no `busy`/flash/range/modal and sharing not refused, one 30 s window at a time, at most 8 per load; a window where a stick moves past `DRIFT_MOVE_SPREAD` is dropped and counted. `window.__senseTelemetryV2()` lists this page's v2 events with their state.

Quick and Guided v2 events carry `beforeAxes` and `afterAxes`; Quick also carries `passAxes`, aligned to `passes` with `null` for an unverified pass. Each measured value is `[[lx,ly],[rx,ry]]` from the existing per-axis median `xy`, converted to signed integer half-LSB units and clamped to ±128 (±64 LSB). No extra HID sampling or commands. The v2 report groups signed final values by board and counts exact nonzero axis repeats across adjacent verified Quick passes; historical v1 radial data cannot provide these.

**Consent.** `sense-telemetry-consent` (`'0'` = off, anything else on), `sense-telemetry-notice` (`'1'` = a notice was answered) and `sense-telemetry-scope` (the description version accepted, `TELEMETRY_SCOPE` = 3). The notice is deliberately short (≤ ~40 words, pinned by `test/telemetry-v2-app.test.js`) but names every v2 category, so **Keep sharing** can accept the scope; the full description lives in the README privacy section (its **Details** link), `privacy.html` and the footer checkbox label. It shows when sharing is on and the accepted scope is below the current version: first visits, and returning sharers whose description changed (with `#notice-changed`). While it is open (`noticeOpen`) nothing leaves, v1 included, so "nothing from this visit has been sent yet" is true for returning sharers. **Keep sharing** writes all three and flushes both queues (v2 in order, one request at a time); **Don't share** writes consent `'0'`, advances a revocation epoch, discards both queues and stops v1 as well; each upload checks consent, notice and epoch again immediately before sending. People who had chosen not to share are not asked again, and no v2 event is even built for them. Unticking a share checkbox is **Don't share** (it resolves an open notice, otherwise turns sharing off and discards the queues). Ticking turns sharing back on; only the footer box, whose label names every category and links the full description, also accepts the current scope. The Quick dialog's box does not, so the v2 categories wait for the notice on the next load. `scripts/pull-telemetry.sh` rsyncs `sessions.jsonl` and `events-v2.jsonl` from the VPS into `data/telemetry/` (gitignored); `ops/calib-telemetry/events-report-cli.mjs` builds the v2 report (save rate by outcome and why not, resting-noise and axis distributions), aggregates only.
