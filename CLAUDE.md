# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Sense Calibrator: a browser tool that diagnoses and hardware-recalibrates drifting PS5 DualSense analog sticks over WebHID. Pure static site — vanilla ES modules, no build step, no runtime dependencies, no linter. `package.json` exists only to run the tests (`npm test` = `node --test`); dev-only tooling lives under `ops/` and `test/` and is never loaded by the page.

## Running

WebHID requires a secure context (`file://` does not work) and only works in Chrome/Edge. Serve the folder over HTTP:

```sh
python3 -m http.server 8000
```

A preview server is configured in `.claude/launch.json` (name `sense-calibrator`, port 8741). Note: actual controller interaction cannot be tested headlessly — it needs a physical DualSense connected over **USB** (Bluetooth is detected and rejected for calibration).

## Architecture

ES modules under `js/`, loaded from `index.html`:

- **`js/ds5.js`** — DualSense HID protocol layer, no DOM. The `DS5` class wraps a WebHID device: calibration commands (feature reports `0x82` send / `0x83` response, checked against expected status words), NVS lock/unlock/status (`0x80`/`0x81`), device info, battery parsing. Protocol sequences derive from the dualshock-tools project. Key invariant: feature report buffers must be padded to the size declared by the HID descriptor (`allocReq`) or the firmware silently discards the command. Every request/response pair runs under a per-device mutex with a 1,000 ms timeout (`HID_REPLY_TIMEOUT_MS`, timers injectable for the simulator). A timeout **poisons** the instance: every later command throws before sending anything, until a reconnect builds a new `DS5`, so a late reply can never be read as the answer to another command. A timeout (or any failure after the send went out) on a commit command — `calibEnd`, `rangeEnd`, `nvsUnlock`, `nvsLock` — sets `error.committed`, and the page raises `unsaved`. `flash()` checks the `0x81` report id, never retries the unlock, retries only the lock once if it fails after a successful unlock, and reports a timeout as "memory state unknown" (`nvUnknown`). `rangeEnd` returns `{ alreadyClosed }` for code 3 (nothing committed). Connecting only reads (`queryNvStatus`, serial, report `0x20`); there is deliberately no auto-lock until hardware check H3. The firmware build date is parsed locally (`parseBuildDate`) and never sent.
- **`js/calib/`** — the calibration algorithm, with no DOM and no direct timers or HID access. The page and the simulator run the same code.
  - `measure.js`: pure measurement — `parseSticks` (report `0x01` bytes → sticks), `median`, `extractStableSamples`, `analyzeDrift`, `summarizeResult`, `verdictFor`, and the `DRIFT_*` thresholds.
  - `sampling.js`: `waitForStable` and `measureOffset`, driven by a stick `source = { subscribe(fn) → unsubscribe, sticks, now() }` and a `clock = { sleep, setTimeout, clearTimeout }`. In the page the source is fed by HID input reports; in the simulator by a virtual DualSense.
  - `quick.js`: `runQuick({ controller, source, clock, isCurrent, isCancelled, force, onProgress, log, params, meta }) → { session, outcome, committed, needsPowerCycle?, … }`. Never throws: an HID error becomes `outcome: 'error'` with `committed` (true once any `calibEnd` succeeded, a `calibBegin` repair committed — the `{ committed }` that `DS5.calibBegin()` returns is read, not only the thrown flag — or a stalled pass left the session open) and `needsPowerCycle` when it exited between a successful `calibBegin` and its `calibEnd` (error, refused sample, failed `calibEnd`, disconnect): the page then marks the power-cycle lock exactly as for a stall (also on the `disconnected` outcome), because the next `calibBegin` would be refused and its repair `calibEnd` would commit the partial session. `repairStaleSession: false` makes a refused `calibBegin` an `error` with `needsPowerCycle` instead of a repair. A `stalled` result carries `pass` and `committedBefore`, so the copy says "nothing was committed" only for a first pass with no repair commit. A session that was only opened is not a commit, so it does not raise `unsaved`. Every commit also emits `onProgress({ phase: 'committed' })`, and the page raises `unsaved` (and the tab flag) right then, not when the run returns: an unplug in pass 2 must still find it set. Other outcomes besides `classifyOutcome`'s: `preflight`, `already-centered` (no command; `force` bypasses), `moved` (hold failed before a later pass), `stalled` (pass abandoned without `calibEnd`, `needsPowerCycle`), `disconnected`, `catastrophic` (verified residual ≥15%). `QUICK_DEFAULTS` holds the constants; a variant is a `params` override. The opt-in recovery pass after `catastrophic` is `runQuick({ …, force: true, params: { maxPasses: 1 } })`.
  - `quick-policy.js`: pure rules — `decideAfterPass` (stop rule) and `classifyOutcome` (which result the user is told). The caller carries the returned state (`prevWorst`, `bestWorst`, `bestPass`, `extraUsed`) into the next pass. Outcome precedence: catastrophic > worse-than-start > lost-ground > worn > residual-deterministic > within-1-step > centered. Plateau continuation (`plateauExtraPasses`) ships at 0 and is enabled only as a separate rollout step. Neither recovery nor plateau continuation adds a pass within one lattice step of the ceiling (`QUICK_CEILING_MARGIN` = 1 LSB·√2, reason `near-ceiling`): from a 14.52 plateau one more pass can land at 15.3.
  - `lattice.js`: the 8-bit lattice (1 LSB = 0.784%, floor 0.555%, one step 1.240%) and **`GRID_TABLE`, the single source of truth** for offset tiers, labels, outcome classes, the precision-test Center score and recommendation keys, plus the Pinned/Moving overrides. `formatOffset` is the only offset formatter (`0.6% · at floor`, `1.2% · 1 step`); `decodeOff` splits an offset into per-axis steps. It imports nothing: `measure.js` takes `DRIFT_OK_MAX`/`DRIFT_MILD_MAX` from it and `verdictFor` goes through the table. `ops/calib-telemetry/quality-report.mjs` loads it too. `DRIFT_OK_MAX` (<1.2, the v1 KPI and stop target) is not raised; "within 1 step" (≤1.25) is a label and a second metric only.
  - `wizard-gate.js` (WS7): the guided wizard's sample gate. Each `calibSample` needs (1) both sticks to have reached the corner since the previous sample (projection toward it ≥0.6, tracked from HID reports), and (2) a stable window (300 ms, 5 s timeout, `QUICK_STABLE_SPREAD`) whose mean is within max(4 LSB, 3·start noise) of the **in-session** rest reference, the first stable window after `calibBegin` (within 50%). Same frame as the samples, as in Quick: `wizard.before` is taken before `calibBegin` and is used only for the before/after comparison (`wizardComparison`, both in the calibrated frame) and for the noise. Never a sample on a timeout, no automatic relaxation; after 2 timeouts the page offers a confirmed, locally logged escape for a creeping stick. The escape never drops the position check: it widens it to a fixed radius of `escapeLsb` (24 LSB ≈ 18.8%, per stick, Euclidean, via `waitForStable`'s `nearRadius`) around the same in-session reference, and widens the spread gate to `DRIFT_MOVE_SPREAD` (never beyond). A thumb held still at a corner or on the rim is never sampled, escape or not; with no reference there is no sample at all (an escape taken before the reference still captures one, with the wider spread gate). Start waits for still sticks before sending anything.
  - `range-coverage.js` (WS7): range tracking fed from HID reports (rAF only draws). Per stick: 36 sectors with chord-conservative fill between samples ≤30° apart, coverage threshold on `min(1, globalMax)`, per-direction extents, turns counted with 30° hysteresis. **Done** needs every direction ≥0.9·maxAbs, ≥2 turns and a change of direction (≥0.5 turn the other way) on both sticks. The page opens Range on an intro step that sends nothing (Cancel and Esc close it) and says, before `rangeBegin`, that once started the only way out without finishing is turning the controller off; with a known pinned axis the intro also warns that the range may never complete (H12). After 15 s an incomplete range can close only through a confirmed **Finish anyway** that names what is missing, and never with a direction under 0.5 (no way to close a zero-motion session; the only exit is turning the controller off). `circularityRms` drives the post-range check ("about 7–10% is normal").
  - `ops.js`: `createOpGate()` — the single-operation `busy` flag with an epoch token (`beginOp`/`endOp`/`reset`). Only the token that currently owns the flag can clear it: an orphan loop that exits after `teardown` (`reset()`) cannot release the `busy` of a newer operation.
- **`js/ui/`** — pure UI logic, no DOM access except the tiny renderers, no HID, no timers:
  - `outcome.js`: the persistent `#calib-outcome` panel (views for Quick, Guided and Range results, per-stick before → after through `formatOffset`), the **Write lock** (`writeLockFor`: `disabled` for catastrophic ≥15%, pinned, stalled/needs power cycle, poisoned, incomplete or `alreadyClosed` range; `guarded` — warning, Cancel focused, second confirmation — for worse-than-start, lost-ground and unverified results; it also checks the numbers, not only the outcome label; an `already-centered` Quick replaces the center state with what it just measured, `committed: false`, so an older catastrophic or worse-than-start verdict never keeps Write off on sticks measured centered), the drift-test message and routing (≥15% → Guided, Pinned → Range then Guided, tentative until H12), and `render` for `ops/sim/replay-telemetry.mjs --renderer`. Invariants: at 15% or more nothing reads as success and Write is disabled; power-off advice only with NVS `locked` (C0-11) — the power cycle needed to clear an open session or a poisoned controller is a different instruction and is always given; a timeout (`error.timeout`/`poisoned`) gets its own view (`POISONED_OUTCOME`: "may or may not have been applied", no earlier pass, no save, no Restart, the raw HID text only in the log); "unplug" only in the sentence saying it is unverified (H11). `FIX_RATE` is the WS3 report figure (PG) and must be refreshed at release. `test/outcome.test.js` covers one case per `GRID_TABLE` row.
  - `hands-off.js`: the green/amber/red movement meter (spread over the last 250 ms, thresholds `QUICK_STABLE_SPREAD` and `DRIFT_MOVE_SPREAD`), fed by HID input reports in the Quick and Guided modals; reusable by the precision test. It sees movement only — a thumb holding a stick still is "Not moving" — so its labels never say "hands off" or "at rest". The page forces the `held` level ("Stick held: let go") whenever it already knows about a hold: Quick phases `held`/`stalled`/`unstable` until the next sample or pass, a failed Quick preflight (except when the last drift test put a stick at Guided-only or Pinned: nobody is touching it, so `quickPreflightRoute` in `outcome.js` says so first and the main button opens Guided, or Range for Pinned), a Guided stick still at the corner (`cornerDot`), and after a Guided gate timeout while a stick is outside the in-session reference tolerance. No new thresholds.
  - `connect-help.js`: the empty-chooser checklist and plain-language WebHID errors.
- **`js/app.js`** — UI wiring only for calibration: connection/reconnect, input report routing (`stickSource`, `pageClock`), drift test, the Quick modal around `runQuick` (busy, messages, outcome panel, telemetry, unsaved), 4-corner guided wizard, range calibration with coverage bins, NVS write flow, telemetry. The Quick loop gets the `ds5` captured at click time and `isCurrent: () => ds5 === controller`; after a replug the orphan loop sends nothing more and touches neither the new operation's `busy` flag nor its modal. A stalled pass, or any error or disconnect that leaves a center session open (Quick or wizard, tracked by `sessionOpen`), marks that controller (`markPowerCycle` → `powerCycleLock`): Quick, wizard, range and Write are refused. The lock follows the controller, not the `DS5` object — Disconnect + Connect, a replug or a reload is not a power-off and the session is still open in the firmware — through the same salted key as `rangeWriteLock` (an unreadable serial counts as the same controller), plus a `sessionStorage` flag (`sense-power-cycle-in-tab`, no device identifier: after a reload it applies to any controller). The flag is also written synchronously **before** every `calibBegin` (Quick through `runQuick`'s `onSession('opening')`, Guided directly; `openSessionGuard` also sets `repairAllowed = false`) and released only after that session's `calibEnd` succeeds or the run ends with no session open: a reload or a closed tab while a session is open (between Guided corners, mid-Quick sampling) never passes through `fail()`/`catch`, and the fresh page must come back blocked and never repair. A `calibBegin` that went out but got no answer (reply timeout, receive error after the send) throws with `openSession: true` (`DS5.calibBegin`), so it is locked like a refused begin. On reconnect the outcome panel shows `powerCycleReminderView`; the lock clears only on evidence of a restart — the HID `disconnect` of that controller within 5 s of a Restart whose send resolved or failed with the device closed (`DS5.reboot()` returns `{ sent }`; a send refused with the device still open keeps the lock and says the restart didn't reach it) — or when the user explicitly confirms a power-off ("I already turned it off"). Second line of defence: once the tab has left a session open, `calibBegin({ repair: false })` is used, so a refused begin fails with `openSession` (and re-marks the lock) instead of committing the partial with a repair `calibEnd`. The Disconnect confirmation says disconnecting is not the power-off it needs. The wizard and range flows are bound to the controller captured at their start too. A range finished incomplete ("Finish anyway"), reported already closed (code 3) or failed after a possible commit sets `rangeWriteLock`: Write is disabled until a complete range replaces it. `finishRange` captures the controller key before `rangeEnd` and sets the lock even when the controller was unplugged while `rangeEnd` was in flight (resolved late, timed out, or failed after teardown: an unknown outcome locks as `error`); only the UI side is skipped then. The lock does not clear on disconnect: whether the range in RAM survives a USB unplug without a power-off is H11 (unverified), so a replug of the same controller keeps it and warns that the incomplete range may still be active, and no copy ever presents a reconnect (or a power-off, H10) as a way to re-enable Write. The lock follows the controller through `rangeWriteLockKey`, a per-page salted SHA-256 of the serial (never the raw serial, never sent anywhere); it is dropped only when both serials are readable and differ, and an unreadable serial counts as the same controller. It is folded into WS5's general Write lock: `currentWriteLock` passes it to `writeLockFor` as a range `incomplete`/`alreadyClosed` state alongside the displayed `rangeState`, and `setRangeWriteLock` only records it and calls `updateWriteLock` (clearing it never re-enables Write while another reason holds). Range results go to the persistent `#calib-outcome` panel, not toasts. Known gap: the lock lives in memory, so a page reload loses it; resolve that once H11 is known. A complete range goes to a check step (one more turn, circularity, no HID command), then the drift test. Range and wizard event fields are local only.
- **`js/quick-center-guard.js`** — the conservative Quick startup radius/hold policy (see below).
- **`js/game.js`** — precision test v4 (WS8), three checks that measure the controller, not the user: **Center** (hands off: offset and noise), **Return** (4 prescribed flicks, 1 round) and **Range** (36 bins from `range-coverage.js`, 25 s cap). `createPrecisionTest()` is a pure state machine (no DOM, no timers; time comes from the caller) and `initGame()` is the DOM shell. Sampling is per HID report through `deps.subscribe` (app.js wires it to `stickSource`); rAF only draws and notices a report gap. Rules: a gap over 100 ms or a hidden tab shows "Interrupted" with Retry; the start is "ready once released" (the WS5 hands-off meter green for 400 ms, or still for 1.5 s on a noisy stick, 12 s cap with an explanation); Center uses 30-report windows, drops those with spread above `DRIFT_MOVE_SPREAD`, treats a rest point that creeps more than 4 LSB between windows as a touch, needs 60% surviving windows, retries automatically at most twice and never scores a touched run; its score is `centerScoreFor` from `GRID_TABLE` (0.555→100, 1.24→90, 3.5→60, 8→0). Return rejects a release slower than 80 ms from r≥0.75 to r≤0.25 ("That looked guided"); a skipped or timed-out Return reads "Not measured", never 0. **Headline**: Calibration = the weaker stick's Center score, Hardware = its Stability (noise; 1 LSB→95, `QUICK_NOISE_WORN`→75, 4%→0), with Return and Range as information-only sub-lines, and one plain sentence. "Previous" is stored under `senseGameLastScore.v4`, keyed by `SHA-256(salt‖serial)` with a random salt kept in `localStorage` (`senseGameSalt.v1`); neither the serial nor the key is stored in the value or sent anywhere. Before/after uses a 1-LSB rule on the per-axis medians (not on the radius). Every wait carries a `why` in `#game-why`; `#game-instr` and `#game-why` are written only on change. The copy's duration ("about 15 seconds") is the rounded median of the model run in `test/game-scoring.test.js`, which fails if the two drift apart. The local `game` event carries raw metrics for re-tuning the Return/Range anchors, never the serial or key. Talks to app.js only through injected deps (`getSticks`, `subscribe`, `getSerial`, `isAvailable`, optional `onReport`); never touches HID.
- **`js/sensitivity.js`** — experimental local sensitivity finder. Compares right-stick tracking across three virtual control speeds, creates a universal FPS aim profile, then optionally maps it to game-specific starting settings. It receives stick state through injected deps, never touches HID, and keeps results in localStorage.
- **`js/playtest.js`** — experimental fixed-timestep FPS-style controller lab. Separates browser frame pacing from raw HID report timing and scores tracking, movement coverage and simultaneous two-stick use. It receives live stick state and HID sample notifications through injected deps.

Sensitivity Finder and Gameplay Lab are excluded from the public product and search metadata. They are available only on localhost with `?preview=1` while they are developed and tested. Do not promote or expose them in the hosted page without an explicit release decision.

Comments in the JS are in Italian; UI strings are English.

## Domain constraints worth knowing

- Applied calibration lives in controller RAM until explicitly written to NVS (unlock → lock cycle via `flash()`); power-off is expected to revert it to the last saved calibration (hardware check H10, not run yet: the copy says "should"). The UI tracks this as the `unsaved` state — don't break that safety net. A `sessionStorage` flag (`sense-unsaved-in-tab`) survives a reload and shows a "may still be active" banner; it deliberately stores no device identifier, and only a successful flash or Dismiss clears it. Disconnect asks for confirmation while `unsaved` or `busy`. The serial is masked by default.
- Only the standard DualSense (`054C:0CE6`) is supported; DualSense Edge and DualShock 4 are not.
- Drift measurement classifies stability by signal *spread* within a short window, not absolute stick value. Stability alone cannot prove that the user released the stick. Quick calibration has a separate conservative startup policy in `js/quick-center-guard.js`: both sticks must stay within 15% radial offset for 300 ms, with at least 10 fresh HID reports and no gap over 100 ms. The baseline must also stay within this radius, and a second centered stability hold is required before any calibration command. This is an initial safety policy, not a hardware diagnosis or a threshold validated from production data; a genuine resting offset outside it requires guided calibration. Failed preflight leaves controller RAM/NVS untouched and restores retry/cancel. Cancelling a blocked attempt resumes the drift test.
- Calibration is blocked only on a **confirmed** state: NVS `unlocked` (a "temporary" calibration could land straight in memory) or a poisoned controller. `unknown`/`error` show a warning chip and still allow it; firmware built in 2020–2021 asks for confirmation once per connection. A flash counts as saved only with no exception and a status other than `unlocked` (to be tightened to `{locked, pending_reboot}` after hardware check H1).
- Quick safety invariants (`js/calib/quick.js`, WS1). **One frame per check**: the centered hold (15% radius, calibrated frame) runs before *every* `calibBegin`; inside a session each sample needs a stable window whose mean is within 4 LSB of the in-session reference (the first stable window after `calibBegin`, itself within a 50% plausibility radius); the verify after `calibEnd` is again in the calibrated frame. Never compare a reading taken before `calibBegin` with one taken during the session, or a session reading with one after `calibEnd`. **12 samples per commit**: a pass that cannot collect them (15 s, prompt, then 30 s more or Cancel) is abandoned without `calibEnd` and the controller needs a power cycle. **Never `calibSample` after a timeout**: a timed-out wait widens the gate (still ≤ `DRIFT_MOVE_SPREAD`; sticky `gateOff` now only pins it at the maximum) but never samples blindly. Starts below `DRIFT_OK_MAX` (both sticks at the floor) send no command; 1.24 starts calibrate. A verified residual ≥15% ends the loop as `catastrophic`, with no automatic recovery pass.
- One calibration at a time: app.js guards with the op gate (`ops.busy`, `js/calib/ops.js`), the former `busy` flag. Alzalo *prima* di qualunque `await` lungo (es. la misura iniziale del wizard), non dopo: la finestra tra il click e l'alzata è sufficiente ad avviare una seconda calibrazione.
- Ogni `calibEnd()` è applicato subito dal firmware e sovrascrive il precedente; il codice non rilegge mai la calibrazione dal controller, quindi **una passata peggiorativa è irreversibile**. Per questo `quickCalibrate` non si ferma su una regressione (userebbe il budget residuo per recuperare), tiene `bestWorst`, e avvisa se il risultato finale è peggiore della migliore passata o del punto di partenza. Non reintrodurre un `break` sul semplice "non è migliorato". `bestWorst` parte dal punto di partenza: un plateau peggiore dell'inizio non è mai "convergenza" (con l'altro stick già a 0.555 si concede al massimo una passata in più, perché ogni passata ricalibra entrambi gli stick). L'unico arresto anticipato è il tetto fisico: una passata verificata ≥15% (il raggio del guard) chiude il ciclo con esito `catastrophic`.
- Il gate di stabilità non deve mai superare `DRIFT_MOVE_SPREAD`: sarebbe più permissivo della soglia con cui l'app stessa dichiara "questa è una mano sullo stick". Decade verso `baseGate` a ogni passata; `gateOff` invece resta sticky, perché riaprirlo costa 5 s di timeout per campione. `Escape` dismisses only the modals in `ESC_DISMISS` and never while `busy` — the range modal only on its intro step (before `rangeBegin`): an open range session must be closed with `rangeEnd()` rather than abandoned, and its Cancel is hidden.
- Stick sampling is always driven by HID input reports (`stickListeners`), never by `setInterval`/`setTimeout`. The drift test too: it completes on the first report after its deadline (samples capped at 3× the expected count), and rAF only draws the progress bar and catches the "no data" case: page timers are throttled in background tabs, and a fixed interval both under-samples the ~250 Hz report rate and duplicates identical samples, which corrupts the stability fraction and the effective duration of `DRIFT_WINDOW`.

## Accessibility (WCAG AA)

- **Focus is owned by the modal block in `js/app.js`** (`openModal`, `closeModal`, the Tab trap, `updateBackgroundInert`). Focusable means visible: `visibleFocusables` filters with `checkVisibility()` (ancestor-walk fallback where it is missing), so buttons inside a hidden container never become the trap's first or last element. Every `.modal-panel` has `tabindex="-1"` and takes the focus when the modal has nothing active (range at open) or when the focused control is disabled or hidden mid-run (Quick and Guided running, game Start, Skip and Retry); a `MutationObserver` on the open modal does this, because disabling a focused button fires no reliable focus event. Initial focus prefers the first visible `[data-autofocus]` in DOM order, else the first focusable, else the panel. Other code only sets or clears `data-autofocus` (WS5 on Cancel/Close; static on Calibrate now, wizard Start and game Start) — never calls `focus()` on modal content itself, except `game.js` moving the focus to the score when the report replaces the hidden Start. The Quick modal must never open on the telemetry checkbox.
- The **`[hidden]` rule** (`display: none !important`) must stay: `hidden` alone loses to class `display` rules such as `.action { display: flex }`.
- **Announcements:** `#quick-msg`, `#wizard-msg`, `#game-instr`, `#game-why` and `#range-hint` are `role="status"`; `#drift-status` and `#calib-outcome` are polite live regions. Errors use `toast(msg, ms, { alert: true })`, which also writes the text into the separate `#alerts` (`role="alert"`) and marks the visible toast `aria-hidden`. Write status text only when it changes (`setLive(el, value, { html })` in app.js compares against the DOM; game.js writes `#game-instr` and `#game-why` through its own compare-first `setText`): rewriting a live region with the same text can be announced again, and the range tick (every 120 ms, on both the range session and its check step), the quick progress events and the game's per-frame view would otherwise do so continuously. Changing text must not chatter either: `#range-hint` carries milestones only (`rangeStatus` counts whole turns, the check step whole percent) and changes at most once per second (`RANGE_HINT_MIN_MS`), except on completion; a counter that moves with the stick never goes into a live region. Progress bars are `role="progressbar"`; `aria-valuenow` and the wizard's "Step n of 5" (`#wizard-step`, the dots are `aria-hidden`) are derived from `style.width` and the dot classes by observers in the accessibility block, so the code that drives them sets only the visual state. Dial canvases are `role="img"` with a label; the drift verdict detail is visible text (`#verdict-*-detail`), never a `title`.
- **Contrast:** text tokens ≥4.5:1 on white and `--bg`; component edges, state dots and dial guides use `--edge` (`#8f8f8a`, 3.25:1 on white) — the canvas `MID` constant in `app.js` is the same value. Focus rings turn white on dark surfaces. `color-scheme: light` only; a dark theme is out of scope (see the plan's "not now").
- The dials' **×10 zoom** is drawing only: the edge is 10%, the dashed ring is `CENTERED_MAX` and the dots are the byte lattice near the center, so the 0.555% floor and the 1.240% step are visible. It never touches measurements or verdicts.

## Tests and simulator

`npm test` runs everything under `test/` (and `ops/calib-telemetry/test/`) with `node --test`, no browser, no controller:

- unit tests for `js/calib/*` (`measure`, `quick-policy`, `quick-preflight`, `quick-center-guard`), `js/ui/*` (`outcome`, `hands-off`) and the telemetry v1 contract;
- `test/ds5-protocol.test.js`: `js/ds5.js` against a scripted WebHID device on the virtual clock (timeout and poison, mutex, commit flags, flash lock/unlock rules, `rangeEnd` code 3, build date, board map);
- `test/lifecycle.test.js` and `test/hotfix-production-defects.test.js` run the **real** `js/app.js` in a `vm` context through `test/helpers/app-harness.mjs`: a DOM stub built from the ids in `index.html`, fake WebHID backed by the simulator's virtual DualSense, and a virtual clock for `setTimeout`, `performance.now` and `requestAnimationFrame`. Known defects are written as `{ todo }` tests that describe the desired behaviour; whoever fixes one removes `todo`;
- `test/sim-equivalence.test.js` compares `runQuick` field by field with golden output produced by the pre-refactor harness on a synthetic population, on the sessions no WS1 rule can touch, and checks the safety invariants on all of them;
- `test/wizard-gate.test.js`, `test/range-coverage.test.js` and `test/guided-and-range.test.js` cover WS7: the pure gates on scripted sources and synthetic rotations, then the real app (thumb held at Continue → 0 samples, creeping stick only through the escape, a thumb held still at a corner never sampled even with the escape, an unplug while `rangeEnd` is in flight still locks Write for the replugged controller, zero motion never enables Done, fast rotation at 60 Hz rAF → 100%, a 1.3× narrow range → 100%, Finish anyway disables Write);
- `test/quick-safety.test.js` covers the WS1 rules on the virtual DualSense, with scripted waits, and on the real app.
- `test/game-scoring.test.js` covers the precision test v4 on the real state machine with the model user of `ops/sim/precision-user.mjs`: bytes 127/128 → Center 100, one step → 90, touches (brush, slow push, endless hold) never scored, a skipped Return "Not measured", report-driven sampling and interruptions, the 1-LSB comparison rule, the salted key, the discrimination rule on the synthetic population, and the dead-wait instrument (every stall over 2 s must carry a `why`; a muted view must fail it). `ops/ui-check/game-check.mjs` (dev only, Playwright passed by path) drives the real page with a scripted fake stick feed, keyboard only, and saves a screenshot of every phase;
- `test/public-surface.test.js` also pins the WS6 accessibility surface (live regions, progressbars, focus attributes, computed contrast of the tokens); `test/ui-a11y.test.js` checks the zoom toggle, verdict detail, alert region and panel fallback on the real app. The real focus trap and the notice-versus-modal overlap need layout, so they run in headless Chromium: `ops/ui-check/a11y-check.mjs` (dev only, Playwright passed by path, every non-localhost request blocked) opens every modal at 375×740, 375×667, 1280 and 1440 px with the telemetry notice showing, checks `elementFromPoint` on each modal button, the initial focus and 20 Tab + 20 Shift+Tab; it also rotates the fake sticks in Range (at most ~1 `#range-hint` change per second) and runs a real catastrophic Quick to check that the outcome panel's buttons are not under the notice after its auto-scroll. The notice's height is published as `--notice-space` (`syncNoticeSpace`): `html` reserves it as `scroll-padding-bottom`, `body` as `padding-bottom`, and `showOutcome` scrolls the action row into view when the panel is taller than the free space.

`ops/sim/` is the headless simulator (see its README): `run.mjs` runs the real `runQuick` against a fitted virtual DualSense, `score.mjs` compares with the real cohort using a cluster bootstrap by template, `replay-sequences.mjs` and `replay-telemetry.mjs` replay the real pass sequences and outcomes through `quick-policy.js`. `release-gates.mjs` runs the whole §4.2 gate matrix against a baseline commit (`git archive` + this `ops/sim`, cached by source hash) and prints every number next to its threshold with PASS/FAIL; gate 5 (report v2 against the plan §1 figures, with the two recorded corrections) is `report-figures.mjs`. The README records the three re-specified gates (final ≥15% normal, forced hold and rim hold; raw values in the INFO rows 3.3i/3.4i/3.5i; pending the plan owner's sign-off, so never reported as passing "as written") and the gates not claimed. Label every simulator result **model-verified**: it is never hardware verification. The real telemetry is gitignored and must never be committed, not even in derived form; tests use only the synthetic population.

`ops/hw-probe/` is the R1 research page (localhost only, spare controller only, see `docs/hw-probe-protocol.md`): it reads the RAM calibration with `0x80 [12,2]` and writes it back with `[12,1]`. Nothing in `js/` may import it or carry a `[12,1]` payload (`test/hw-probe-public-surface.test.js`), and the irreversibility invariant in *Domain constraints* stays in force until the protocol's go/no-go is filled in from a hardware run.

## Telemetry

Every significant action emits a typed local event via `recordEvent(kind, data)` in app.js. Ogni evento porta `sid`, un valore casuale per caricamento di pagina mai persistito: collega gli eventi di una singola visita, non due visite tra loro. `summarizeResult` include `xy` (componenti per asse): `off` è la loro ipotenusa, quindi senza `xy` la direzione del drift è perduta. Events always go to `localStorage` (`sense-calib-sessions`, capped at 200; on a quota error the history is trimmed to 50 and the write retried, and only a `SecurityError` disables storage for the page).

The network contract is deliberately narrower. `js/telemetry.js` maps only complete `quick` sessions (no `aborted` marker, e.g. `'moved'`, and no local-only `truncated: 'time-limit'`) to the strict nine-field v1 API schema and strips `kind`, `sid`, `xy` and every unsupported field. All other events stay local. Do not widen the v1 payload or allow unknown properties. Richer network events require a versioned endpoint, matching OpenAPI and privacy documentation, and contract tests. The first-launch banner still holds events until the person chooses **Keep sharing**; choosing **Don't share** discards the queue. `scripts/pull-telemetry.sh` rsyncs collected sessions from the VPS into `data/telemetry/` (gitignored).
