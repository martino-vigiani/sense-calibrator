# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Sense Calibrator: a browser tool that diagnoses and hardware-recalibrates drifting PS5 DualSense analog sticks over WebHID. Pure static site — vanilla ES modules, no build step, no runtime dependencies, no linter. `package.json` exists only to run the tests (`npm test` = `node --test`); dev-only tooling lives under `ops/` and `test/` and is never loaded by the page.

## Running

WebHID requires a secure context (`file://` does not work) and only works in Chrome/Edge. Serve the folder over HTTP:

```sh
python3 -m http.server 8000
```

A preview server is configured in `.claude/launch.json` (name `sense-calibrator`, port 8741). Note: actual controller interaction cannot be tested headlessly — it needs a physical DualSense connected over **USB** (Bluetooth is detected and rejected for calibration).

## Architecture

ES modules under `js/`, loaded from `index.html`:

- **`js/ds5.js`** — DualSense HID protocol layer, no DOM. The `DS5` class wraps a WebHID device: calibration commands (feature reports `0x82` send / `0x83` response, checked against expected status words), NVS lock/unlock/status (`0x80`/`0x81`), device info, battery parsing. Protocol sequences derive from the dualshock-tools project. Key invariant: feature report buffers must be padded to the size declared by the HID descriptor (`allocReq`) or the firmware silently discards the command. Every request/response pair runs under a per-device mutex with a 1,000 ms timeout (`HID_REPLY_TIMEOUT_MS`, timers injectable for the simulator). A timeout **poisons** the instance: every later command throws before sending anything, until a reconnect builds a new `DS5`, so a late reply can never be read as the answer to another command. A timeout (or any failure after the send went out) on a commit command — `calibEnd`, `rangeEnd`, `nvsUnlock`, `nvsLock` — sets `error.committed`, and the page raises `unsaved`. `flash()` checks the `0x81` report id, never retries the unlock, retries only the lock once if it fails after a successful unlock, and reports a timeout as "memory state unknown" (`nvUnknown`). `rangeEnd` returns `{ alreadyClosed }` for code 3 (nothing committed). Connecting only reads (`queryNvStatus`, serial, report `0x20`); there is deliberately no auto-lock until hardware check H3. The firmware build date is parsed locally (`parseBuildDate`) and never sent.
- **`js/calib/`** — the calibration algorithm, with no DOM and no direct timers or HID access. The page and the simulator run the same code.
  - `measure.js`: pure measurement — `parseSticks` (report `0x01` bytes → sticks), `median`, `extractStableSamples`, `analyzeDrift`, `summarizeResult`, `verdictFor`, and the `DRIFT_*` thresholds.
  - `sampling.js`: `waitForStable` and `measureOffset`, driven by a stick `source = { subscribe(fn) → unsubscribe, sticks, now() }` and a `clock = { sleep, setTimeout, clearTimeout }`. In the page the source is fed by HID input reports; in the simulator by a virtual DualSense.
  - `quick.js`: `runQuick({ controller, source, clock, isCurrent, isCancelled, force, onProgress, log, params, meta }) → { session, outcome, committed, needsPowerCycle?, … }`. Never throws: an HID error becomes `outcome: 'error'` with `committed` (true once any `calibEnd` succeeded, a `calibBegin` repair committed, or a stalled pass left the session open). Other outcomes besides `classifyOutcome`'s: `preflight`, `already-centered` (no command; `force` bypasses), `moved` (hold failed before a later pass), `stalled` (pass abandoned without `calibEnd`, `needsPowerCycle`), `disconnected`, `catastrophic` (verified residual ≥15%). `QUICK_DEFAULTS` holds the constants; a variant is a `params` override. The opt-in recovery pass after `catastrophic` is `runQuick({ …, force: true, params: { maxPasses: 1 } })`.
  - `quick-policy.js`: pure rules — `decideAfterPass` (stop rule) and `classifyOutcome` (which result the user is told). The caller carries the returned state (`prevWorst`, `bestWorst`, `bestPass`, `extraUsed`) into the next pass. Outcome precedence: catastrophic > worse-than-start > lost-ground > worn > residual-deterministic > within-1-step > centered. Plateau continuation (`plateauExtraPasses`) ships at 0 and is enabled only as a separate rollout step.
  - `lattice.js`: the 8-bit lattice (1 LSB = 0.784%, floor 0.555%, one step 1.240%) and **`GRID_TABLE`, the single source of truth** for offset tiers, labels, outcome classes, the precision-test Center score and recommendation keys, plus the Pinned/Moving overrides. `formatOffset` is the only offset formatter (`0.6% · at floor`, `1.2% · 1 step`); `decodeOff` splits an offset into per-axis steps. It imports nothing: `measure.js` takes `DRIFT_OK_MAX`/`DRIFT_MILD_MAX` from it and `verdictFor` goes through the table. `ops/calib-telemetry/quality-report.mjs` loads it too. `DRIFT_OK_MAX` (<1.2, the v1 KPI and stop target) is not raised; "within 1 step" (≤1.25) is a label and a second metric only.
  - `ops.js`: `createOpGate()` — the single-operation `busy` flag with an epoch token (`beginOp`/`endOp`/`reset`). Only the token that currently owns the flag can clear it: an orphan loop that exits after `teardown` (`reset()`) cannot release the `busy` of a newer operation.
- **`js/ui/`** — pure UI logic, no DOM access except the tiny renderers, no HID, no timers:
  - `outcome.js`: the persistent `#calib-outcome` panel (views for Quick, Guided and Range results, per-stick before → after through `formatOffset`), the **Write lock** (`writeLockFor`: `disabled` for catastrophic ≥15%, pinned, stalled/needs power cycle, poisoned, incomplete or `alreadyClosed` range; `guarded` — warning, Cancel focused, second confirmation — for worse-than-start, lost-ground and unverified results; it also checks the numbers, not only the outcome label), the drift-test message and routing (≥15% → Guided, Pinned → Range then Guided, tentative until H12), and `render` for `ops/sim/replay-telemetry.mjs --renderer`. Invariants: at 15% or more nothing reads as success and Write is disabled; power-off advice only with NVS `locked` (C0-11); "unplug" only in the sentence saying it is unverified (H11). `FIX_RATE` is the WS3 report figure (PG) and must be refreshed at release. `test/outcome.test.js` covers one case per `GRID_TABLE` row.
  - `hands-off.js`: the green/amber/red "hands off" meter (spread over the last 250 ms, thresholds `QUICK_STABLE_SPREAD` and `DRIFT_MOVE_SPREAD`), fed by HID input reports in the Quick and Guided modals; reusable by the precision test.
  - `connect-help.js`: the empty-chooser checklist and plain-language WebHID errors.
- **`js/app.js`** — UI wiring only for calibration: connection/reconnect, input report routing (`stickSource`, `pageClock`), drift test, the Quick modal around `runQuick` (busy, messages, outcome panel, telemetry, unsaved), 4-corner guided wizard, range calibration with coverage bins, NVS write flow, telemetry. The Quick loop gets the `ds5` captured at click time and `isCurrent: () => ds5 === controller`; after a replug the orphan loop sends nothing more and touches neither the new operation's `busy` flag nor its modal. A stalled pass marks that controller (`powerCycleController`): Quick, wizard, range and Write are refused until it is reconnected.
- **`js/quick-center-guard.js`** — the conservative Quick startup radius/hold policy (see below).
- **`js/game.js`** — self-contained precision test with three calibration-diagnostic checks (center hold / edge reach / snap-back), each measuring a calibration property rather than user skill. Talks to app.js only through injected deps (`getSticks`, `isAvailable`, optional `onReport`); never touches HID.
- **`js/sensitivity.js`** — experimental local sensitivity finder. Compares right-stick tracking across three virtual control speeds, creates a universal FPS aim profile, then optionally maps it to game-specific starting settings. It receives stick state through injected deps, never touches HID, and keeps results in localStorage.
- **`js/playtest.js`** — experimental fixed-timestep FPS-style controller lab. Separates browser frame pacing from raw HID report timing and scores tracking, movement coverage and simultaneous two-stick use. It receives live stick state and HID sample notifications through injected deps.

Sensitivity Finder and Gameplay Lab are excluded from the public product and search metadata. They are available only on localhost with `?preview=1` while they are developed and tested. Do not promote or expose them in the hosted page without an explicit release decision.

Comments in the JS are in Italian; UI strings are English.

## Domain constraints worth knowing

- Applied calibration lives in controller RAM until explicitly written to NVS (unlock → lock cycle via `flash()`); power-off reverts it. The UI tracks this as the `unsaved` state — don't break that safety net. A `sessionStorage` flag (`sense-unsaved-in-tab`) survives a reload and shows a "may still be active" banner; it deliberately stores no device identifier, and only a successful flash or Dismiss clears it. Disconnect asks for confirmation while `unsaved` or `busy`. The serial is masked by default.
- Only the standard DualSense (`054C:0CE6`) is supported; DualSense Edge and DualShock 4 are not.
- Drift measurement classifies stability by signal *spread* within a short window, not absolute stick value. Stability alone cannot prove that the user released the stick. Quick calibration has a separate conservative startup policy in `js/quick-center-guard.js`: both sticks must stay within 15% radial offset for 300 ms, with at least 10 fresh HID reports and no gap over 100 ms. The baseline must also stay within this radius, and a second centered stability hold is required before any calibration command. This is an initial safety policy, not a hardware diagnosis or a threshold validated from production data; a genuine resting offset outside it requires guided calibration. Failed preflight leaves controller RAM/NVS untouched and restores retry/cancel. Cancelling a blocked attempt resumes the drift test.
- Calibration is blocked only on a **confirmed** state: NVS `unlocked` (a "temporary" calibration could land straight in memory) or a poisoned controller. `unknown`/`error` show a warning chip and still allow it; firmware built in 2020–2021 asks for confirmation once per connection. A flash counts as saved only with no exception and a status other than `unlocked` (to be tightened to `{locked, pending_reboot}` after hardware check H1).
- Quick safety invariants (`js/calib/quick.js`, WS1). **One frame per check**: the centered hold (15% radius, calibrated frame) runs before *every* `calibBegin`; inside a session each sample needs a stable window whose mean is within 4 LSB of the in-session reference (the first stable window after `calibBegin`, itself within a 50% plausibility radius); the verify after `calibEnd` is again in the calibrated frame. Never compare a reading taken before `calibBegin` with one taken during the session, or a session reading with one after `calibEnd`. **12 samples per commit**: a pass that cannot collect them (15 s, prompt, then 30 s more or Cancel) is abandoned without `calibEnd` and the controller needs a power cycle. **Never `calibSample` after a timeout**: a timed-out wait widens the gate (still ≤ `DRIFT_MOVE_SPREAD`; sticky `gateOff` now only pins it at the maximum) but never samples blindly. Starts below `DRIFT_OK_MAX` (both sticks at the floor) send no command; 1.24 starts calibrate. A verified residual ≥15% ends the loop as `catastrophic`, with no automatic recovery pass.
- One calibration at a time: app.js guards with the op gate (`ops.busy`, `js/calib/ops.js`), the former `busy` flag. Alzalo *prima* di qualunque `await` lungo (es. la misura iniziale del wizard), non dopo: la finestra tra il click e l'alzata è sufficiente ad avviare una seconda calibrazione.
- Ogni `calibEnd()` è applicato subito dal firmware e sovrascrive il precedente; il codice non rilegge mai la calibrazione dal controller, quindi **una passata peggiorativa è irreversibile**. Per questo `quickCalibrate` non si ferma su una regressione (userebbe il budget residuo per recuperare), tiene `bestWorst`, e avvisa se il risultato finale è peggiore della migliore passata o del punto di partenza. Non reintrodurre un `break` sul semplice "non è migliorato". `bestWorst` parte dal punto di partenza: un plateau peggiore dell'inizio non è mai "convergenza" (con l'altro stick già a 0.555 si concede al massimo una passata in più, perché ogni passata ricalibra entrambi gli stick). L'unico arresto anticipato è il tetto fisico: una passata verificata ≥15% (il raggio del guard) chiude il ciclo con esito `catastrophic`.
- Il gate di stabilità non deve mai superare `DRIFT_MOVE_SPREAD`: sarebbe più permissivo della soglia con cui l'app stessa dichiara "questa è una mano sullo stick". Decade verso `baseGate` a ogni passata; `gateOff` invece resta sticky, perché riaprirlo costa 5 s di timeout per campione. `Escape` dismisses only the modals in `ESC_DISMISS` and never while `busy` — the range modal is deliberately excluded, since an open range session must be closed with `rangeEnd()` rather than abandoned.
- Stick sampling is always driven by HID input reports (`stickListeners`), never by `setInterval`/`setTimeout`. The drift test too: it completes on the first report after its deadline (samples capped at 3× the expected count), and rAF only draws the progress bar and catches the "no data" case: page timers are throttled in background tabs, and a fixed interval both under-samples the ~250 Hz report rate and duplicates identical samples, which corrupts the stability fraction and the effective duration of `DRIFT_WINDOW`.

## Accessibility (WCAG AA)

- **Focus is owned by the modal block in `js/app.js`** (`openModal`, `closeModal`, the Tab trap, `updateBackgroundInert`). Focusable means visible: `visibleFocusables` filters with `checkVisibility()` (ancestor-walk fallback where it is missing), so buttons inside a hidden container never become the trap's first or last element. Every `.modal-panel` has `tabindex="-1"` and takes the focus when the modal has nothing active (range at open) or when the focused control is disabled or hidden mid-run (Quick and Guided running, game Start); a `MutationObserver` on the open modal does this, because disabling a focused button fires no reliable focus event. Initial focus prefers the first visible `[data-autofocus]` in DOM order, else the first focusable, else the panel. Other code only sets or clears `data-autofocus` (WS5 on Cancel/Close; static on Calibrate now, wizard Start and game Start) — never calls `focus()` on modal content itself, except `game.js` moving the focus to the score when the report replaces the hidden Start. The Quick modal must never open on the telemetry checkbox.
- The **`[hidden]` rule** (`display: none !important`) must stay: `hidden` alone loses to class `display` rules such as `.action { display: flex }`.
- **Announcements:** `#quick-msg`, `#wizard-msg`, `#game-instr` and `#range-hint` are `role="status"`; `#drift-status` and `#calib-outcome` are polite live regions. Errors use `toast(msg, ms, { alert: true })`, which also writes the text into the separate `#alerts` (`role="alert"`) and marks the visible toast `aria-hidden`. Write status text only when it changes (`setLive(el, value, { html })` in app.js compares against the DOM; game.js guards `#game-instr` inline): rewriting a live region with the same text can be announced again, and the range tick (every 120 ms), the quick progress events and the game's flick phase would otherwise do so continuously. Progress bars are `role="progressbar"`; `aria-valuenow` and the wizard's "Step n of 5" (`#wizard-step`, the dots are `aria-hidden`) are derived from `style.width` and the dot classes by observers in the accessibility block, so the code that drives them sets only the visual state. Dial canvases are `role="img"` with a label; the drift verdict detail is visible text (`#verdict-*-detail`), never a `title`.
- **Contrast:** text tokens ≥4.5:1 on white and `--bg`; component edges, state dots and dial guides use `--edge` (`#8f8f8a`, 3.25:1 on white) — the canvas `MID` constant in `app.js` is the same value. Focus rings turn white on dark surfaces. `color-scheme: light` only; a dark theme is out of scope (see the plan's "not now").
- The dials' **×10 zoom** is drawing only: the edge is 10%, the dashed ring is `CENTERED_MAX` and the dots are the byte lattice near the center, so the 0.555% floor and the 1.240% step are visible. It never touches measurements or verdicts.

## Tests and simulator

`npm test` runs everything under `test/` (and `ops/calib-telemetry/test/`) with `node --test`, no browser, no controller:

- unit tests for `js/calib/*` (`measure`, `quick-policy`, `quick-preflight`, `quick-center-guard`), `js/ui/*` (`outcome`, `hands-off`) and the telemetry v1 contract;
- `test/ds5-protocol.test.js`: `js/ds5.js` against a scripted WebHID device on the virtual clock (timeout and poison, mutex, commit flags, flash lock/unlock rules, `rangeEnd` code 3, build date, board map);
- `test/lifecycle.test.js` and `test/hotfix-production-defects.test.js` run the **real** `js/app.js` in a `vm` context through `test/helpers/app-harness.mjs`: a DOM stub built from the ids in `index.html`, fake WebHID backed by the simulator's virtual DualSense, and a virtual clock for `setTimeout`, `performance.now` and `requestAnimationFrame`. Known defects are written as `{ todo }` tests that describe the desired behaviour; whoever fixes one removes `todo`;
- `test/sim-equivalence.test.js` compares `runQuick` field by field with golden output produced by the pre-refactor harness on a synthetic population, on the sessions no WS1 rule can touch, and checks the safety invariants on all of them;
- `test/quick-safety.test.js` covers the WS1 rules on the virtual DualSense, with scripted waits, and on the real app.
- `test/public-surface.test.js` also pins the WS6 accessibility surface (live regions, progressbars, focus attributes, computed contrast of the tokens); `test/ui-a11y.test.js` checks the zoom toggle, verdict detail, alert region and panel fallback on the real app. The real focus trap and the notice-versus-modal overlap need layout, so they run in headless Chromium: `ops/ui-check/a11y-check.mjs` (dev only, Playwright passed by path, every non-localhost request blocked) opens every modal at 375, 1280 and 1440 px with the telemetry notice showing, checks `elementFromPoint` on each modal button, the initial focus and 20 Tab + 20 Shift+Tab.

`ops/sim/` is the headless simulator (see its README): `run.mjs` runs the real `runQuick` against a fitted virtual DualSense, `score.mjs` compares with the real cohort using a cluster bootstrap by template, `replay-sequences.mjs` and `replay-telemetry.mjs` replay the real pass sequences and outcomes through `quick-policy.js`. Label every simulator result **model-verified**: it is never hardware verification. The real telemetry is gitignored and must never be committed, not even in derived form; tests use only the synthetic population.

`ops/hw-probe/` is the R1 research page (localhost only, spare controller only, see `docs/hw-probe-protocol.md`): it reads the RAM calibration with `0x80 [12,2]` and writes it back with `[12,1]`. Nothing in `js/` may import it or carry a `[12,1]` payload (`test/hw-probe-public-surface.test.js`), and the irreversibility invariant in *Domain constraints* stays in force until the protocol's go/no-go is filled in from a hardware run.

## Telemetry

Every significant action emits a typed local event via `recordEvent(kind, data)` in app.js. Ogni evento porta `sid`, un valore casuale per caricamento di pagina mai persistito: collega gli eventi di una singola visita, non due visite tra loro. `summarizeResult` include `xy` (componenti per asse): `off` è la loro ipotenusa, quindi senza `xy` la direzione del drift è perduta. Events always go to `localStorage` (`sense-calib-sessions`, capped at 200; on a quota error the history is trimmed to 50 and the write retried, and only a `SecurityError` disables storage for the page).

The network contract is deliberately narrower. `js/telemetry.js` maps only complete `quick` sessions to the strict nine-field v1 API schema and strips `kind`, `sid`, `xy` and every unsupported field. All other events stay local. Do not widen the v1 payload or allow unknown properties. Richer network events require a versioned endpoint, matching OpenAPI and privacy documentation, and contract tests. The first-launch banner still holds events until the person chooses **Keep sharing**; choosing **Don't share** discards the queue. `scripts/pull-telemetry.sh` rsyncs collected sessions from the VPS into `data/telemetry/` (gitignored).
